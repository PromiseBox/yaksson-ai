💡 여기서 바로 읽히는 사실 3가지

1. 데이터→PostgreSQL→Cloud SQL 경로가 이미 코드로 존재(이관 덤프까지). GCP 타깃 확정.

2. 애플리케이션 백엔드(FastAPI) 레포가 없음 → “판정 동작”은 로컬 Mock에만 있고 팀 자산화·실데이터 연동이 안 됨.

3. 실제 DB는 PostgreSQL 단일. Neo4j/GraphRAG는 어떤 레포에도 코드가 없음(계획만).

② 🔴 “다이어그램 vs 현실” 갭 — Neo4j/GraphRAG는 코드가 0

실제 DB는 PostgreSQL 단일인데, 확정 아키텍처 그림엔 Neo4j Knowledge Graph가 화려하게 그려져 있음 → 발표 때 ‘과장 아키텍처’ 비판 위험.

→ MVP에선 Neo4j를 빼고 PostgreSQL로 가는 것을 강력 권장(핵심 7종 판정은 관계형으로 충분). 그릴 거면 만들고, 안 만들 거면 MVP 다이어그램에서 빼기.

③ ⚠️ 데이터 품질 함정 — 정작 자주 뜨는 항목의 “사유 문구”가 비어 있음

화면에 보여줄 근거 문구(PROHBT_CONTENT)가 노인주의 76.8%·효능군중복 93.3% 누락(병용금기는 ~3%로 양호).

→ 빈 사유는 LLM이 채우지 말고, 카테고리 표준문구 + 출처표기 + 약사 라우팅으로 처리(로컬 코드에 이미 그 패턴 있음). 상세는 §5.

🔴 왜 위험한가

화면에 보여줄 “근거 문구(사유)”가 PROHBT_CONTENT인데, 가장 흔히 뜨는 노인주의·효능군중복에서 거의 비어 있음. 정책이 없으면 (a) 빈 사유로 신뢰 저하, 또는 (b) LLM이 사유를 지어내는 환각 — 둘 다 치명적.

✅ 권고 처리 정책 (반드시 합의)

• 사유 공백 시 카테고리 표준 문구로 대체(예: 노인주의 → “고령자에서 주의가 필요한 약물로 등재되어 있습니다(식약처 노인주의 목록). 상세는 약사·의사 확인 권고.”) — 로컬 코드의 rec.prohibit_content or "..." 패턴 이식.

• 출처(테이블·공고번호·공고일자)는 항상 표기 — 사유가 비어도 “등재됨”은 사실이라 신뢰 가능.

• LLM에 사유 생성 금지. 효능군중복은 “같은 효능군 2개 이상” 규칙 자체가 근거.

• intrcQesitm(상호작용) 결측을 “안전”으로 해석 금지 → “정보 없음”으로. 노인주의(112행)·효능군중복(405행)은 성분 단위 소형 참조표 → 품목↔성분코드 조인 커버리지 점검.

6 주의 · 조언 · 제안 종합

⚖️ 법규 · 안전 (최우선)

  • 표시·광고: “공식/실시간 연동/국가표준 준수/정밀 대조”는 사실과 달라 허위·과장 리스크 → “식약처 등재 정보를 참고한 위험 가능성 안내 보조 도구”로.
  • 의료기기 규제 경계: 식습관·운동은 “추천/치료”로 가면 규제영역 → “복용 중 주의 정보 + 약사·의사 상담”으로만 한정.
  • 진단·처방 단정 금지: 중단/증량/감량/신규복용/진단 어휘 금지 → 출력에 금칙어 필터 권장.
  • 개인정보: MVP는 별칭·나이·성별 최소수집, 민감정보는 선택+동의. 약봉투 이미지는 OCR 텍스트만 저장, 원본 미보관이 가장 안전.

🔐 기술 · 운영

  • 공유 OpenAI 키(40달러)는 서버 전용 — 프론트 노출 0, Secret Manager. ui_prototype Public이므로 레포 히스토리에 실제 키 커밋 여부 점검(있었다면 폐기·재발급).
  • 공공 API 폴백: 1차는 DB 조회(이미 적재)라 의존도 낮음 — 좋음. OCR/LLM은 외부 의존이므로 타임아웃·레이트리밋·실패 폴백 준비.
  • 재현율 측정 자동화: 골든셋 고정 → CI 회귀. 로컬 13개 테스트를 backend로 가져가 확장.
  • SSOT 확립: “제품 레포 1개 + 아키텍처 README”로 세 갈래(로컬/프로토/팀레포) 혼선 종식. Notion=의사결정, GitHub=코드.

🎯 일정 · 범위 (공모전 관점)

  • MVP를 좁혀라: 3화면 + 핵심 7종 판정 + 출처/약사라우팅 + GPT-4o 설명 = 심사에서 이기는 최소집합.
  • 차별화 1컷: “정부 데이터를 내 부모 약에 대입 → 출처 달린 경고 → Eval 통과/환각 0” 데모. 경쟁 우위는 화려함이 아니라 신뢰성.
  • 과욕 경계: Neo4j·모바일 네이티브·식습관/운동 풀구현은 ‘시간 있으면’ 확장. MVP 필수 아님.
